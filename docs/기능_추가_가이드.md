# 기능 추가 가이드 (프론트엔드)

이 문서는 화면 기능을 새로 만들 때 **어떤 파일을 어디에 만들고, 기존 파일에는 무엇만 고치는지** 를 정한 규칙이다.
지금 구조는 [`프론트엔드_구조맵.md`](./프론트엔드_구조맵.md) 에 있다. 이 가이드를 읽기 전에 구조맵의 1~5장을 먼저 본다.

## 0. 기본 원칙

> **새 기능 = 새 파일.** 기존 파일은 새 파일을 "연결하는 한 줄"만 고친다.

- JS 는 기능마다 모듈 파일을 새로 만들고, 페이지 시작점(`main.js` 등)에서 import 해서 호출한다.
- HTML 은 화면 일부면 `fragments/` 에 조각을 새로 만들고, 새 화면이면 새 템플릿을 만든다.
- 이렇게 하면 여러 명이 동시에 작업해도 같은 파일을 고치는 일이 줄어서 충돌이 적고, PR 리뷰도 "새 파일 + 연결 몇 줄" 만 보면 된다.

## 1. 먼저 정할 것: 어떤 종류의 기능인가

```text
새 기능
 ├─ 기존 화면(main) 안에 붙는가?  → A. 조각 + 모듈          (예시 1: 장소 종류 선택)
 ├─ 새 화면(URL)이 필요한가?      → B. 새 페이지             (예시 2: 만남 기록 페이지)
 └─ JS 가 서버에 데이터만 묻는가? → C. /api/... + api/ 모듈  (지금의 /api/route/car/path 처럼)
```

| 종류 | 새로 만드는 파일 | 연결을 위해 고치는 파일 |
| --- | --- | --- |
| A. 화면 안 기능 | `fragments/<기능>.html`, `js/<폴더>/<기능>.js`, (필요하면) `js/api/<대상>.js` | `main.html` 에 `th:replace` 한 줄, `main.js` 에 import + 호출 |
| B. 새 페이지 | `<Page>Controller.java`, `templates/<page>.html`, `css/<page>.css`, `js/<page>.js`, `js/<page>/*.js` | `fragments/header.html` 에 메뉴 링크, (회원 전용인데 `/mypage/` 밖의 주소면) `SecurityConfig` — 2-4 |
| C. 서버 API | `<기능>Controller.java` (`@RestController`, `/api/...`), `js/api/<대상>.js` | 그 API 를 쓰는 모듈 |

## 2. 파일 배치·이름 규칙

### 2-1. 어디에 무엇을

| 무엇 | 위치 | 이름 규칙 | 예 |
| --- | --- | --- | --- |
| 페이지 템플릿 | `templates/` | 소문자. URL 경로·시작점 JS·페이지 CSS 와 같은 이름 | `meetings.html` ↔ `/meetings` ↔ `js/meetings.js` ↔ `css/meetings.css` |
| HTML 조각 | `templates/fragments/` | camelCase | `placeKeyword.html`, `meetingCard.html` |
| 조각 이름 (`th:fragment`) | 조각 파일 안 | camelCase, **HTML 태그 이름과 다르게** | `siteHeader` (O), `header` (X) |
| 페이지 시작점 JS | `static/js/` 바로 아래 | 페이지 이름과 같게 | `main.js`, `meetings.js` |
| 기능 모듈 JS | `static/js/<폴더>/` | camelCase | `map/places.js`, `meetings/deleteMeeting.js` |
| 외부 호출 JS | `static/js/api/` | 호출 대상 이름 | `geocoder.js`, `routeApi.js`, `placeSearch.js` |
| 페이지 CSS | `static/css/` | 페이지 이름과 같게 | `main.css`, `meetings.css` |
| 공통 CSS | `static/css/base.css` | - | 두 페이지 이상에서 쓰는 스타일만 |
| 서비스 인터페이스 | `service/` | `<기능>Service` | `MemberService`, `RouteService` (2-5) |
| 서비스 구현체 | `service/impl/` | `<기능>ServiceImpl` | `MemberServiceImpl`, `RouteServiceImpl` (2-5) |

**JS 폴더 고르는 기준**

| 폴더 | 들어가는 것 |
| --- | --- |
| `map/` | 지도 위에 그리는 것 (마커, 선, 말풍선). 다른 페이지에서도 재사용할 수 있다 |
| `participants/` | main 화면의 참가자 입력 폼 동작 |
| `api/` | 카카오 서비스(주소·장소 검색), 우리 서버 `/api/...` 호출. 화면을 건드리지 않는다 |
| `<page>/` | 새 페이지 전용 기능 (예: `meetings/`) |

### 2-2. 함수 이름

| 시작 단어 | 뜻 | 예 |
| --- | --- | --- |
| `init…` | 요소에 이벤트를 연결한다 (한 번 호출) | `initSubmit`, `initParticipantList` |
| `create…` | 무언가를 만들어 돌려준다 | `createMap` |
| `show…` / `draw…` | 화면(지도)에 그린다 | `showCurrentLocation`, `drawResult` |
| `search…` / `fetch…` / `…To…` | 외부에 묻고 결과를 Promise 로 돌려준다 (`api/`) | `fetchCarRoute`, `addressToCoords` |
| `read…` | 이미 있는 값을 읽는다 | `readAppData` |

### 2-3. id · class

- 새로 만드는 id 와 class 는 **kebab-case** 로 짓는다. 예: `place-keyword`, `meeting-list`
- 기존 camelCase id(`participantForm`, `addParticipant` 등)는 JS 가 쓰고 있으므로 이번 규칙 때문에 바꾸지 않는다.
- 변형 스타일은 기본 클래스에 `--` 를 붙여 **같이** 쓴다. 예: `class="info-window info-window--place"`

### 2-4. 로그인이 필요한 페이지 (`config/SecurityConfig.java`)

- 보안 규칙은 **"로그인이 필요한 곳만 막고, 나머지는 누구나"** 다. 지금 막는 곳은 `/mypage/**` 하나다.
- **로그인이 필요한 페이지는 주소를 `/mypage/...` 아래에 만든다.** 그러면 `SecurityConfig` 를 고치지 않아도 보호된다.
- 다른 주소를 써야 한다면 `SecurityConfig` 의 `requestMatchers(...)` 에 그 주소를 **반드시** 추가한다. 빠뜨리면 로그인하지 않은 사람도 들어올 수 있다.
- 없는 주소나 서버 오류는 로그인 여부와 상관없이 공통 오류 화면(`templates/error.html`)이 나온다.

```java
.requestMatchers("/mypage/**")          // 로그인이 필요한 주소들
.authenticated()
.anyRequest()                           // 그 밖의 모든 주소
.permitAll()
```

### 2-5. 서비스는 인터페이스 + 구현체로 나눈다 (`service/`, `service/impl/`)

- **인터페이스** (`service/<기능>Service.java`): 메서드 목록만 둔다. 메서드마다 **무엇을 하는지, 실패하면 무엇을 던지는지** 주석을 단다.
- **구현체** (`service/impl/<기능>ServiceImpl.java`): 실제 코드. `@Service`, `@Transactional`, 필드, 생성자, `private` 도우미 메서드는 여기에 둔다. 구현한 메서드에는 `@Override` 를 붙인다.
- **컨트롤러는 인터페이스 타입으로 받는다.** (`private final MemberService memberService;`) 구현체가 하나면 Spring 이 알아서 넣어 준다.
- 서비스끼리만 쓰는 내부 도우미(`MeetingPointAdjuster` 등)는 나누지 않아도 된다.

```java
// service/MemberService.java
public interface MemberService {
    // 회원탈퇴. 회원 정보를 지우고, 올린 프로필 사진 파일도 지운다.
    void deleteAccount(String id);
}

// service/impl/MemberServiceImpl.java
@Service
public class MemberServiceImpl implements MemberService {
    @Override
    @Transactional
    public void deleteAccount(String id) { ... }
}
```

## 3. JS 모듈 작성 규칙

| # | 규칙 | 이유 |
| --- | --- | --- |
| J1 | 페이지마다 시작점은 하나. 시작점은 **조립만** 한다 (DOM 찾기, 데이터 읽기, 모듈 호출) | 페이지에서 무슨 일이 일어나는지 시작점만 보면 알 수 있게 |
| J2 | 모듈은 `export function` 만 둔다. **파일 맨 위에서 바로 실행되는 코드를 두지 않는다.** 특히 `new kakao...` 는 반드시 함수 안에서 | import 하는 순간 에러가 나면 페이지의 JS 전체가 멈춘다 |
| J3 | `document.getElementById` 는 시작점에서만. 모듈은 요소를 **인자로** 받는다 | 모듈이 어떤 HTML 에 의존하는지 함수 매개변수에 드러나게 |
| J4 | 전역 변수 금지. 여러 모듈이 쓰는 값(`map` 등)은 시작점에서 한 번 만들어 인자로 넘긴다 | 이름 충돌과 실행 순서 문제를 막기 위해 |
| J5 | 서버 값은 `window.APP_DATA` 에 키를 추가하고, `appData.js` 에서 기본값과 함께 꺼낸다 | 서버 → JS 통로를 하나로 유지 |
| J6 | 외부 호출(`fetch`, `kakao.maps.services.*`)은 `api/` 에서 **Promise** 로 감싼다. 화면 모듈은 직접 호출하지 않는다 | 화면 코드는 "결과를 받아 그리기" 만 하게 |
| J7 | 좌표는 항상 `{ lat, lng }`. 카카오의 `x`(경도) / `y`(위도) 변환은 `api/` 안에서만 | x·y 순서 실수를 한 곳에 가둔다 |
| J8 | import 경로는 `./` 또는 `../` 로 시작하고 `.js` 까지 쓴다. 경로는 **import 하는 파일 기준** | 확장자를 빼면 404 → 전체 멈춤 |
| J9 | 시작점에서는 카카오 없이 동작하는 기능(폼 등)을 먼저 호출하고, 지도는 나중에 | 지도 SDK 가 실패해도 폼은 쓸 수 있게 |
| J10 | 사용자가 입력한 값은 HTML 문자열에 이어 붙이지 않는다. `textContent` 를 쓰거나 요소를 만들어 넣는다 | 입력값에 태그가 있으면 그대로 실행·표시된다 |
| J11 | 나중에 추가되는 요소(+ 버튼으로 생긴 칸 등)의 이벤트는 부모에 한 번 붙인다 (이벤트 위임) | 추가될 때마다 이벤트를 다시 붙이지 않아도 된다 |

**모듈 기본 모양**

```js
// js/<폴더>/<기능>.js
import { 필요한함수 } from '../api/<대상>.js';

let 모듈안상태 = [];   // 이 파일 안에서만 쓰는 상태는 OK (전역 아님). 단 kakao 객체 생성은 함수 안에서

// 이 기능이 무엇을 하는지 한 줄 설명.
export function initXxx(필요한요소, 필요한값) {
    // ...
}
```

## 4. HTML · 템플릿 규칙

| # | 규칙 | 이유 / 주의 |
| --- | --- | --- |
| H1 | 새 화면은 새 템플릿. `<head>` 는 `fragments/head :: common('제목')`, 상단은 `fragments/header :: siteHeader` 를 반드시 쓴다 | 공통 부분은 한 곳에서만 고치게 |
| H2 | 화면 일부 기능은 `fragments/` 에 조각으로 만들고, 페이지에는 `th:replace` **한 줄**만 넣는다 | 페이지 파일이 "조립도" 로 남게 |
| H3 | 조각에 필요한 값은 **매개변수**로 받는다. 예: `participant(index, num, p)` | 어떤 값이 필요한 조각인지 선언부에 드러나게 |
| H4 | `th:each` 와 `th:replace` 를 한 태그에 쓰지 않는다. `<th:block th:each>` 로 감싼다 | `th:replace` 가 먼저 실행돼서 반복이 안 된다 |
| H5 | 조각은 `th:replace` 로 넣는다 (`th:insert` 아님) | `insert` 는 바깥 태그가 이중으로 남는다 |
| H6 | 조각 경로는 `templates/` 기준, `.html` 을 쓰지 않는다. 예: `~{fragments/head :: common('로그인')}` | |
| H7 | JS 가 복제할 마크업은 `<template>` + **같은 조각**으로 만든다. 번호 자리는 `@NAME@` 처럼 쓰고, **밑줄 두 개(`__`)는 쓰지 않는다** | `__...__` 는 Thymeleaf 전처리 문법이라 에러가 난다 |
| H8 | `<template>` 은 반복되는 요소들의 부모(예: `#participants`) **밖에** 둔다 | 자식 개수로 인원수를 세는 코드가 틀어진다 |
| H9 | 서버 값을 JS 로 넘길 때는 `th:inline="javascript"` 의 `window.APP_DATA` 하나만 쓰고, 이 스크립트는 **폼 뒤**에 둔다 | 폼 앞에 길게 두면 CSRF 토큰을 못 만들고 화면이 잘린다 |
| H10 | null 일 수 있는 값(`meetingPoint` 등)은 `th:if` 안에서 쓰거나 `?.` 로 읽는다 | 렌더링 에러 → 오류 화면(500)이 뜬다. 원인은 서버 콘솔의 에러 로그에서 본다 |
| H11 | 인라인 `style=""`, `onclick=""` 를 쓰지 않는다. (실행 중에 정해지는 색 같은 값만 예외) | 스타일은 CSS, 동작은 JS 모듈에 |
| H12 | 링크와 리소스 주소는 `th:href="@{...}"`, `th:src="@{...}"` | 서버 경로가 바뀌어도 자동으로 맞춰진다 |
| H13 | 태그는 **여는 태그와 닫는 태그를 짝으로** 추가·삭제한다. 포매터를 돌린 뒤 들여쓰기가 갑자기 당겨진 곳이 없는지 본다 | 여분의 `</div>` 하나로 폼과 결과 배치가 깨진 적이 있다 |
| H14 | 외부 SDK `<script>`(카카오 등)는 그 SDK 를 쓰는 페이지에만 넣는다. 공통 head 에 넣지 않는다 | |

**새 페이지 템플릿 기본 모양**

```html
<!DOCTYPE html>
<html lang="ko" xmlns:th="http://www.thymeleaf.org">

<head>
    <th:block th:replace="~{fragments/head :: common('페이지 제목')}"></th:block>
    <link rel="stylesheet" th:href="@{/css/<page>.css}">
</head>

<body>
    <header th:replace="~{fragments/header :: siteHeader}"></header>

    <!-- 화면 본문. 기능 단위는 fragments/ 조각을 th:replace 로 -->

    <!-- 서버 값이 JS 에 필요할 때만 -->
    <script th:inline="javascript">
        window.APP_DATA = {
            // 키: /*[[${모델값}]]*/ 기본값
        };
    </script>
    <!-- JS 동작이 있을 때만 -->
    <script type="module" th:src="@{/js/<page>.js}"></script>
</body>

</html>
```

## 5. 예시 1 — main 화면에 "장소 종류 선택" 추가하기 (종류 A)

지금은 `map/places.js` 에서 `'카페'` 를 고정으로 검색한다. 폼에 장소 종류 선택칸을 추가하고, 고른 종류로 검색하게 바꾼다.

### 만들고 고치는 파일

| 순서 | 파일 | 새로 / 수정 | 할 일 |
| --- | --- | --- | --- |
| 1 | `repository/ParticipantForm.java` | 수정 | `keyword` 필드 추가 (기본값 `"카페"`) |
| 2 | `fragments/placeKeyword.html` | **새로** | 장소 종류 선택칸 조각 |
| 3 | `main.html` | 수정 (2줄) | 조각 연결 1줄, `APP_DATA` 에 `keyword` 1줄 |
| 4 | `js/appData.js` | 수정 | `keyword` 꺼내기 |
| 5 | `js/api/placeSearch.js` | **새로** | 카카오 장소 검색을 Promise 로 감싸기 |
| 6 | `js/map/places.js` | 수정 | `keyword` 를 받아 `api/placeSearch.js` 사용 |
| 7 | `js/main.js` | 수정 (1줄) | `searchNearbyPlaces` 에 `keyword` 전달 |

컨트롤러와 서비스는 고치지 않는다. `@ModelAttribute ParticipantForm` 이 `keyword` 를 자동으로 받아서 다시 화면에 넘겨 준다.

### 1) ParticipantForm.java

```java
private String keyword = "카페";   // 장소 종류. 폼의 <select name="keyword"> 와 이름이 같아야 한다.

public String getKeyword() { return keyword; }
public void setKeyword(String keyword) { this.keyword = keyword; }
```

### 2) fragments/placeKeyword.html (새로)

```html
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<!-- 장소 종류 선택칸. selected : 지금 선택된 값 (제출 후에도 유지하려고 받는다) -->
<fieldset th:fragment="placeKeyword(selected)">
    <legend>장소 종류</legend>
    <select name="keyword" id="place-keyword">
        <option value="카페"   th:selected="${selected == '카페'}">카페</option>
        <option value="음식점" th:selected="${selected == '음식점'}">음식점</option>
        <option value="술집"   th:selected="${selected == '술집'}">술집</option>
    </select>
</fieldset>
</html>
```

### 3) main.html (연결 2줄)

```html
<!-- form#participantForm 안, 버튼들 위 -->
<fieldset th:replace="~{fragments/placeKeyword :: placeKeyword(*{keyword})}"></fieldset>
```

```js
// 맨 아래 window.APP_DATA 에 한 줄 추가
keyword: /*[[${participantForm?.keyword}]]*/ '카페'
```

### 4) appData.js

```js
return {
    meetingPoint: appData.meetingPoint || null,
    participants: appData.participants || [],
    keyword: appData.keyword || '카페'
};
```

### 5) api/placeSearch.js (새로)

```js
// 기준 위치(center) 주변 radius(m) 안에서 keyword 로 장소를 찾는다. 가까운 순.
// 결과가 없으면 빈 배열, 오류면 reject.
export function searchPlacesByKeyword(keyword, center, radius) {
    return new Promise((resolve, reject) => {
        const ps = new kakao.maps.services.Places();   // 함수 안에서 생성 (J2)
        ps.keywordSearch(keyword, (data, status) => {
            if (status === kakao.maps.services.Status.OK) resolve(data);
            else if (status === kakao.maps.services.Status.ZERO_RESULT) resolve([]);
            else reject(new Error(status));
        }, {
            location: new kakao.maps.LatLng(center.lat, center.lng),
            radius: radius,
            sort: kakao.maps.services.SortBy.DISTANCE
        });
    });
}
```

> 돌려주는 장소 객체는 카카오 원본(`place.x`, `place.y`, `place.place_name`, `place.id`)이다. `carRoutes.js` 가 이 모양을 쓰고 있어서, `{ lat, lng }` 로 바꾸는 건 구조맵의 "남은 과제" 로 따로 한다.

### 2) SecurityConfig

- 지금 설정은 **막을 주소만** 적고 나머지는 누구나 볼 수 있다(`anyRequest().permitAll()`). (2-4)
- 만남 기록은 회원 기능인데 주소가 `/mypage/` 밖(`/meetings`)이므로, 막을 주소에 **추가해야 한다.**
  ```java
  .requestMatchers("/mypage/**", "/meetings/**")
  .authenticated()
  ```
  - 주소를 `/mypage/meetings` 로 만들었다면 수정할 필요가 없다.
- 추가한 뒤 로그인하지 않고 `/meetings` 에 들어가 `/login` 으로 이동하는지 확인한다. **이동하지 않고 화면이 보이면 보호되지 않은 것이다.**
- 페이지가 렌더링 중에 에러가 나면 공통 오류 화면(500)이 뜬다. 원인은 **서버 콘솔의 에러 로그**에서 본다.
