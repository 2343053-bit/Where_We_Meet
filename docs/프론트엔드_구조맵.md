# 프론트엔드 구조맵 (main 화면)

이 문서는 `main.html` 을 중심으로 화면의 각 영역을 **누가 그리고(서버 템플릿), 누가 움직이는지(JS 모듈)** 를 정리한 지도다.
코드 옆에 열어 두고 같이 보는 용도로 쓴다.

- 새 기능을 만들 때의 규칙은 [`기능_추가_가이드.md`](./기능_추가_가이드.md) 를 본다.
- 줄 번호는 코드가 바뀌면 금방 어긋나므로, 이 문서는 **id·함수 이름·파일 이름** 으로 위치를 가리킨다. 코드에서 찾을 때는 이 이름으로 검색한다.

## 1. 한눈에 보기

```text
브라우저 GET /main
    ↓
LocationController.getLocations()      ← 빈 참가자 2명(ParticipantForm), kakaoJsKey 를 모델에 담음
    ↓
main.html 렌더링 (Thymeleaf)           ← fragments/ 의 조각들을 끼워 넣어 HTML 완성
    ↓
window.APP_DATA 에 서버 값 저장         ← main.html 맨 아래 인라인 스크립트
    ↓
js/main.js 실행 (시작점)               ← 필요한 모듈을 import 해서 순서대로 호출
    ├─ participants/*  : 입력 폼 동작
    └─ map/*           : 지도 그리기
              └─ api/* : 외부 API 호출 (카카오, 우리 서버 /api)
```

**핵심 규칙 세 가지**

1. HTML 을 만드는 건 서버(템플릿·fragment), 동작을 붙이는 건 JS 다.
2. 페이지마다 JS 시작점은 하나다. `main.html` 은 `<script type="module" src="/js/main.js">` 하나만 불러온다.
3. 서버 값은 `window.APP_DATA` 하나로만 JS 에 전달한다.

## 2. 파일 지도

```text
src/main/resources
├── templates
│   ├── main.html                  # 메인 화면. 조각을 조립하고 JS 시작점을 불러온다
│   ├── login.html / signup.html
│   └── fragments                  # 여러 곳에서 쓰는 HTML 조각
│       ├── head.html              # common(title)      : <head> 공통 내용 (charset, title, base.css)
│       ├── header.html            # siteHeader         : 상단 메뉴
│       └── participant.html       # participant(index, num, p) : 참가자 입력칸 1개
│
└── static
    ├── css
    │   ├── base.css               # 모든 페이지 공통
    │   └── main.css               # main 화면 전용 (#map 크기, 폼/결과 배치, 말풍선 .info-window)
    └── js
        ├── main.js                # main 화면 시작점 (조립만 한다)
        ├── appData.js             # readAppData()      : window.APP_DATA 읽기
        ├── participants           # 참가자 입력 폼
        │   ├── participantList.js # initParticipantList() : + / - 버튼
        │   ├── addressSearch.js   # initAddressSearch()   : 주소 검색 팝업
        │   └── submit.js          # initSubmit()          : 제출 시 주소 → 좌표 변환 후 제출
        ├── map                    # 지도 위에 그리는 것
        │   ├── createMap.js       # createMap()           : 지도 생성
        │   ├── currentLocation.js # showCurrentLocation() : 현재 위치 마커
        │   ├── resultMarkers.js   # drawResult()          : 중간 지점·참가자 마커, 지도 범위 맞춤
        │   ├── places.js          # searchNearbyPlaces()  : 중간 지점 주변 카페 마커
        │   └── carRoutes.js       # showCarRoutes()       : 카페 클릭 → 참가자별 경로 선·이동시간
        └── api                    # 외부 호출 (Promise 로 감싼다)
            ├── geocoder.js        # addressToCoords()     : 주소 → { lat, lng } (카카오)
            └── routeApi.js        # fetchCarRoute()       : 승용차 경로 (우리 서버 /api/route/car/path)
```

## 3. main.html 와이어프레임

### 3-1. 화면 배치

```text
┌────────────────────────────────────────────────────────────────┐
│ <header>                       fragments/header :: siteHeader  │
├────────────────────────────────────────────────────────────────┤
│ div#map                        map/createMap.js                │
│   - current location marker    map/currentLocation.js          │
│   - meeting point / people     map/resultMarkers.js            │
│   - nearby cafes               map/places.js                   │
│       - click -> route lines   map/carRoutes.js                │
│                                  -> api/routeApi.js            │
│ p#current-location-status      map/currentLocation.js          │
├────────────────────────────────────────────────────────────────┤
│ div#form-results  (grid: form | results)                       │
│ ┌─ form#participantForm ──────────┐ ┌─ section#results ──────┐ │
│ │ div#participants                │ │ th:if meetingPoint     │ │
│ │   fieldset x N                  │ │ (server only, no JS)   │ │
│ │   fragments/participant         │ │                        │ │
│ │   [address search] button       │ │                        │ │
│ │     participants/addressSearch  │ │                        │ │
│ │ template#participant-template   │ │                        │ │
│ │ [-] [+]                         │ │                        │ │
│ │   participants/participantList  │ │                        │ │
│ │ [submit]                        │ │                        │ │
│ │   participants/submit           │ │                        │ │
│ │     -> api/geocoder             │ │                        │ │
│ └─────────────────────────────────┘ └────────────────────────┘ │
└────────────────────────────────────────────────────────────────┘

  <script type="module" src="/js/main.js">
```

### 3-2. 태그별 담당 파일

`main.html` 위에서 아래 순서다.

| 태그 / id | 그리는 쪽 (서버) | 동작시키는 쪽 (JS) | 비고 |
| --- | --- | --- | --- |
| `<head>` | `fragments/head :: common('참가자 위치 입력')` + `main.css` | - | base.css → main.css 순서 유지 |
| `<header>` | `fragments/header :: siteHeader` | - | 메뉴 수정은 header.html 만 |
| `div#map` | 빈 div | `createMap` → `showCurrentLocation` → `drawResult` → `searchNearbyPlaces` | 크기는 `main.css` 의 `#map` |
| `p#current-location-status` | 숨김(`hidden`) | `showCurrentLocation` | 위치 권한 거부 등 안내 문구 |
| 카카오 SDK `<script>` | `kakaoJsKey` 로 주소 생성 | 모든 `kakao.*` 사용처 | `libraries=services` (주소·장소 검색) |
| Postcode `<script>` | - | `addressSearch.js` | 주소 검색 팝업 (`daum.Postcode`) |
| `div#form-results` | 폼과 결과를 감싸는 grid | - | `main.css` |
| `form#participantForm` | `th:object="${participantForm}"`, `th:action="@{/main}"` (CSRF 토큰 자동 삽입) | `initSubmit` 이 submit 이벤트를 가로챔 | |
| `div#participants` | `th:each` 로 `fragments/participant` 를 인원수만큼 | `initParticipantList`, `initAddressSearch` (이벤트 위임) | 자식 fieldset 개수 = 인원수 |
| `fieldset` (참가자 1명) | `fragments/participant :: participant(index, num, p)` | - | name 은 `participants[i].participantName / latitude / longitude` |
| `.address` 입력칸 | readonly, **name 없음** | `addressSearch.js` 가 채움, `submit.js` 가 읽음 | 서버로 전송되지 않음 |
| `.searchAddress` 버튼 | 조각 안 | `addressSearch.js` | |
| hidden 위도·경도 | 조각 안 | `submit.js` 가 제출 직전에 채움 | |
| `template#participant-template` | 같은 조각을 `('@INDEX@', '@NUM@', null)` 로 | `participantList.js` 가 복제 | `#participants` **밖**에 있어야 함 |
| `#removeParticipant`, `#addParticipant` | 버튼 | `participantList.js` | 2~5명 제한 |
| 제출 버튼 | `type="submit"` | `submit.js` | |
| `section#results` | `th:if="${meetingPoint != null}"` | - | 제출 후에만 보임 |
| 인라인 `<script th:inline="javascript">` | `window.APP_DATA` 생성 | `appData.js` 가 읽음 | 폼 **뒤**에 둔다 (CSRF 관련 주석 참고) |
| `<script type="module" src="/js/main.js">` | - | 시작점 | 이 페이지의 유일한 모듈 스크립트 |

## 4. 서버 → 화면 데이터

### 4-1. 모델에 담기는 값 (`LocationController`)

| 이름 | GET /main | POST /main | 쓰는 곳 |
| --- | --- | --- | --- |
| `participantForm` | 빈 참가자 2명 | 제출한 참가자 N명 (이름·위도·경도) | 폼(`th:each`), `APP_DATA.participants` |
| `kakaoJsKey` | O | O (`@ModelAttribute addAttributes`) | 카카오 SDK `<script>` 주소 |
| `meetingPoint` | 없음(null) | `MeetingPointService.findMeetingPoint()` 결과 | `section#results`, `APP_DATA.meetingPoint` |

### 4-2. `window.APP_DATA` 모양

```js
window.APP_DATA = {
    meetingPoint: null,                         // 제출 후: { meetingLatitude: 35.1, meetingLongitude: 128.9 }
    participants: [                             // participantForm.participants 그대로
        { participantName: "", latitude: null, longitude: null },
        { participantName: "", latitude: null, longitude: null }
    ]
};
```

JS 에서는 `readAppData()` (`appData.js`) 로만 읽는다. 값이 없으면 `{ meetingPoint: null, participants: [] }` 를 돌려준다.

## 5. main.js 실행 순서

```text
main.js
 1. readAppData()                       서버 값 꺼내기
 2. initParticipantList(...)            + / - 버튼          ┐ 폼 쪽을 먼저 둔다.
 3. initAddressSearch(...)              주소 검색 버튼       │ 지도(카카오) 쪽에서 에러가 나도
 4. initSubmit(...)                     제출 가로채기        ┘ 폼은 동작하게 하기 위해서
 5. createMap(#map)                     지도 생성
 6. showCurrentLocation(map, ...)       현재 위치 (비동기)
 7. drawResult(map, ...)                중간 지점·참가자 마커 + 범위 맞춤
 8. searchNearbyPlaces(map, ...)        제출 후(meetingPoint 있음)에만
```

`map` 객체는 5번에서 **한 번만** 만들고, 필요한 함수에 인자로 넘긴다. 전역 변수는 없다.

### import 관계

```text
main.js
├── appData.js
├── participants/participantList.js
├── participants/addressSearch.js
├── participants/submit.js ──────────── api/geocoder.js
├── map/createMap.js
├── map/currentLocation.js
├── map/resultMarkers.js
└── map/places.js ── map/carRoutes.js ── api/routeApi.js
```

> 이 중 **한 파일이라도 불러오다 에러가 나면 main.js 전체가 실행되지 않는다** (지도와 폼이 모두 멈춤).
> 화면이 통째로 안 뜨면 F12 Console 의 첫 번째 빨간 줄에서 파일 이름과 줄 번호를 확인한다.

## 6. 사용자 동작별 흐름

### + / - 버튼

```text
#addParticipant 클릭
    ↓ participantList.js
template#participant-template 의 HTML 복사 → @INDEX@ / @NUM@ 을 번호로 바꿈
    ↓
#participants 맨 뒤에 추가 → 버튼 활성/비활성 갱신 (2~5명)
```

`-` 는 맨 마지막 칸만 지운다. 그래서 name 번호가 항상 0, 1, 2… 로 이어진다.

### 주소 검색

```text
.searchAddress 클릭 (#participants 에 붙인 이벤트 위임 → 나중에 추가된 칸도 동작)
    ↓ addressSearch.js
daum.Postcode 팝업 → 선택한 도로명 주소를 같은 fieldset 의 .address 에 넣음
```

### 제출

```text
제출 버튼
    ↓ submit.js (기본 제출을 막음)
1) 빈 주소 확인 → 있으면 "참가자 N의 주소를 검색해 주세요." 후 중단
2) addressToCoords() 로 모든 주소를 동시에 변환 (api/geocoder.js → 카카오 Geocoder)
   → 실패가 있으면 "참가자 N의 주소를 찾을 수 없습니다." 후 중단
3) hidden 위도·경도 채우고 form.submit()
    ↓
POST /main → LocationController.postLocations()
    → MeetingPointService.findMeetingPoint() → 모델에 meetingPoint
    ↓
main.html 다시 렌더링 (제출한 인원수만큼 입력칸, section#results 표시, 지도에 마커)
```

> 제출 후 화면에서 주소 칸은 비어 있다. 주소는 서버로 보내지 않기 때문이다. (아래 남은 과제)

### 카페 마커 클릭

```text
카페 마커 클릭 (places.js 가 붙인 이벤트)
    ↓ carRoutes.js
이전 경로 선 지우기 → 말풍선 "계산 중..."
    ↓ 참가자마다 fetchCarRoute() (api/routeApi.js)
GET /api/route/car/path?originLat=&originLng=&destLat=&destLng=
    → RouteController.getCarRoute() → RouteService (카카오모빌리티 길찾기)
    ↓ 모든 응답이 오면
참가자별 색깔 경로 선 + 말풍선 "■ 이름: 승용차 N분"
(그사이 다른 카페를 눌렀으면 이 결과는 버림)
```

## 7. 외부 의존

| 대상 | 불러오는 곳 | 쓰는 파일 | 키 |
| --- | --- | --- | --- |
| 카카오 지도 SDK (`services` 포함) | main.html `<script>` | map/*, api/geocoder.js | `kakao.js-key` (application-secret.properties) |
| 다음 우편번호 (Postcode) | main.html `<script>` | participants/addressSearch.js | 필요 없음 |
| 우리 서버 `/api/route/car/path` | `fetch` | api/routeApi.js | 서버가 `kakao.rest-api-key` 사용 |

`SecurityConfig` 에서 `/main`, `/css/**`, `/js/**`, `/api/**` 는 로그인 없이 접근할 수 있다.

## 8. 알려진 남은 과제

현재 코드에서 [`기능_추가_가이드.md`](./기능_추가_가이드.md) 의 규칙과 다른 부분이다. 새 코드는 가이드를 따르고, 아래 항목은 별도 작업으로 정리한다.

| 항목 | 위치 | 내용 |
| --- | --- | --- |
| 변수 이름·선언 | `main.js`, `map/*` | `meetingLat/meetingLng` 를 `meetingPoint` 객체로, `var` → `const/let` |
| 사용자 입력을 HTML 문자열에 삽입 | `resultMarkers.js`, `carRoutes.js` 말풍선 | 참가자 이름에 태그를 넣으면 태그로 해석된다 |
| 장소 검색이 api/ 밖에 있음 | `map/places.js` | `kakao.maps.services.Places` 를 직접 사용 (가이드 예시 1에서 정리) |
| 카카오 장소 객체의 x / y | `places.js`, `carRoutes.js` | 좌표를 `{ lat, lng }` 로 바꾸지 않고 `place.y`, `place.x` 를 그대로 씀 |
| 제출 후 주소 칸이 빔 | `ParticipantLocation` | `address` 필드가 없어서 다시 제출하려면 주소를 다시 검색해야 함 |
| 제출 연타 | `submit.js` | 좌표 변환 중에 다시 누르면 두 번 제출될 수 있음 |
| 기존 id 이름 규칙 | `main.html` | `participantForm`, `addParticipant` 등 camelCase 와 kebab-case 가 섞여 있음 |
