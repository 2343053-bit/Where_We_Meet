# 로그인·회원가입 동작 원리

이 문서는 회원가입과 로그인 요청이 어떤 객체를 거쳐 처리되는지 설명한다.

## 주요 객체

| 객체 | 역할 |
| --- | --- |
| `MemberController` | 회원가입과 로그인 화면 요청을 받는다. |
| `MemberService` | 회원가입 검증, 비밀번호 암호화, 회원 저장을 담당한다. |
| `MemberRepository` | `Member` 엔티티를 데이터베이스에서 조회·저장·수정·삭제한다. |
| `Member` | 회원 정보를 표현하는 JPA 엔티티다. |
| `PasswordEncoder` | 비밀번호를 BCrypt 방식으로 암호화하고 로그인 시 검증한다. |
| `SecurityConfig` | 요청별 접근 권한과 로그인·로그아웃 규칙을 설정한다. |
| `CustomUserDetailsService` | 로그인 아이디로 회원을 조회해 Spring Security가 사용할 사용자 정보로 변환한다. |
| `SecurityFilterChain` | HTTP 요청이 통과하는 보안 필터 묶음이다. |

## 회원가입 흐름

### 1. 회원가입 화면 요청

```text
GET /signup
    ↓
MemberController.showSignupForm()
    ↓
signup.html 반환
```

`MemberController`는 폼에서 사용할 빈 `Member` 객체를 `memberForm`이라는 이름으로 화면에 전달한다.

### 2. 회원가입 폼 제출

```text
POST /signup
    ↓
MemberController.processSignup()
    ↓
MemberService.signup()
```

`@ModelAttribute("memberForm")`은 HTML 폼의 입력값을 `Member` 객체에 연결한다.

### 3. 회원가입 처리

`MemberService.signup()`은 다음 순서로 실행된다.

```text
username 중복 확인
    ↓
nickname 중복 확인
    ↓
비밀번호 BCrypt 암호화
    ↓
MemberRepository.save(member)
    ↓
데이터베이스 저장
```

`@Transactional`은 이 작업을 하나의 트랜잭션으로 묶는다. 처리 중 예외가 발생하면 데이터베이스 변경을 롤백할 수 있다.

비밀번호는 평문으로 저장되지 않는다.

```text
입력 비밀번호 → PasswordEncoder → BCrypt 암호문 → 데이터베이스
```

저장이 완료되면 컨트롤러는 `/login`으로 리다이렉트한다.

## 로그인 흐름

### 1. 로그인 화면 요청

```text
GET /login
    ↓
MemberController.showLoginForm()
    ↓
login.html 반환
```

로그인 화면을 보여주는 `GET /login`은 컨트롤러가 처리한다.

### 2. 로그인 폼 제출

로그인 폼은 다음 주소로 요청을 보낸다.

```html
<form action="/login" method="post">
```

```text
POST /login
    ↓
SecurityFilterChain
    ↓
Spring Security 로그인 필터
    ↓
CustomUserDetailsService.loadUserByUsername()
    ↓
MemberRepository.findByUsername()
    ↓
PasswordEncoder로 비밀번호 검증
```

`POST /login`을 처리하는 컨트롤러 메서드는 작성하지 않는다. `SecurityConfig`의 `loginProcessingUrl("/login")` 설정에 따라 Spring Security가 이 요청을 가로채 처리한다.

### 3. 회원 조회

`CustomUserDetailsService`는 Spring Security로부터 로그인 아이디를 전달받는다.

```java
Member member = memberRepository.findByUsername(username)
        .orElseThrow(() -> new UsernameNotFoundException(...));
```

`MemberRepository`는 메서드 이름을 분석해 `username`이 일치하는 회원을 조회한다.

조회한 `Member`는 Spring Security가 이해할 수 있는 `UserDetails`로 변환된다.

```java
return User.builder()
        .username(member.getUsername())
        .password(member.getPassword())
        .roles("USER")
        .build();
```

### 4. 비밀번호 검증

Spring Security는 사용자가 입력한 평문 비밀번호와 데이터베이스에 저장된 BCrypt 암호문을 `PasswordEncoder`로 비교한다.

```text
비밀번호 일치
    → 인증 성공

비밀번호 불일치 또는 회원 없음
    → 인증 실패
```

### 5. 로그인 결과

인증에 성공하면:

```text
인증 성공
    ↓
/main으로 리다이렉트
    ↓
인증된 사용자로 보호된 페이지 접근
```

인증에 실패하면:

```text
/login?error=true로 리다이렉트
```

## URL별 처리 주체

| 요청 | 처리 주체 | 설명 |
| --- | --- | --- |
| `GET /signup` | `MemberController` | 회원가입 화면 반환 |
| `POST /signup` | `MemberController` → `MemberService` | 회원 검증 및 저장 |
| `GET /login` | `MemberController` | 로그인 화면 반환 |
| `POST /login` | Spring Security | 회원 조회 및 비밀번호 검증 |
| `GET /main` | 해당 컨트롤러 | 로그인된 사용자만 접근 가능 |
| `POST /logout` | Spring Security | 로그아웃 처리 후 로그인 화면으로 이동 |

## `MemberRepository`의 데이터 관리

```java
public interface MemberRepository
        extends JpaRepository<Member, String> {
}
```

`JpaRepository`는 `Member` 엔티티를 관리하는 기본 데이터 접근 기능을 제공한다.

- `Member`: 관리할 엔티티
- `String`: 엔티티 기본 키 `username`의 타입

따라서 별도의 SQL을 작성하지 않아도 다음 기능을 사용할 수 있다.

```java
memberRepository.save(member);       // 저장 또는 수정
memberRepository.findById(username); // 기본 키로 조회
memberRepository.findAll();          // 전체 조회
memberRepository.delete(member);     // 삭제
```

다음 메서드는 Spring Data JPA가 메서드 이름을 분석해 쿼리를 생성한다.

```java
findByUsername(String username)
existsByUsername(String username)
existsByNickname(String nickname)
```

## 전체 흐름 요약

```text
회원가입:
POST /signup
 → MemberController
 → MemberService
 → PasswordEncoder
 → MemberRepository.save()
 → 데이터베이스

로그인:
POST /login
 → SecurityFilterChain
 → CustomUserDetailsService
 → MemberRepository.findByUsername()
 → PasswordEncoder
 → 성공 시 /main
```
